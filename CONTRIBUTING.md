# Contributing

## Setup

Requires Node.js 24 or newer. The app is built with [Vite](https://vite.dev/) and has no runtime
dependencies; Vite and TypeScript are dev dependencies.

```sh
npm install
npm run dev            # dev server at http://localhost:8123, reloads on change
npm run dev -- --host  # also reachable from a phone on the same Wi-Fi
npm run build          # production build in dist/
npm run preview        # build, then serve dist/ at http://localhost:8124
npm run typecheck
```

With `--host`, open the printed `http://192.168...` address on the phone. Everything works there
except offline use and "Add to Home Screen", which need https.

The build (`vite.config.mjs`) turns `src/index.html` into one JS bundle and one stylesheet. The
small data files are bundled in, the model weights are a separate content-hashed file, and
`src/public/` (manifest, icons) is copied as-is. A small plugin in the config writes `dist/sw.js`
(offline support) from `src/sw.js`, with the list of built files and a version hash.

The model and card data in `src/data/` are generated by the Python tooling in `tooling/` (card
library, synthetic training data, training, export). [TRAINING.md](TRAINING.md) explains how to
train a new model and what photos to take; [tooling/README.md](tooling/README.md) describes each
script.
The home-screen icons in `src/public/` are rendered from `src/public/icon.svg` by
`node scripts/make-icons.mjs`.

## Layout

- `src/`: the app (TypeScript, HTML, CSS). `src/pipeline/` has no UI and also runs in Node.
- `src/data/`: generated card layouts, deck symbols and model weights.
- `src/public/`: files copied into the build unchanged (manifest, icons).
- `scripts/`: one-off helpers (`make-icons.mjs`).
- `tests/`: Node and headless-browser tests; `tests/fixtures/` is their committed test data.
- `tooling/`: build-time Python. Never shipped.
- `training-data/`: your photos for training and testing (see [TRAINING.md](TRAINING.md)). Not in
  source control.
- `out/`: everything the tooling and tests make. Not in source control; delete it any time.

## How it works

1. **Detector** (`src/pipeline/engine-*.ts`): a tiny convolutional network (180k weights, 0.7 MB)
   finds every card's centre badge (shape, value, side, colour, orientation) and every visible dot.
   It runs on the GPU with plain WebGL2 shaders, or on the CPU as a fallback.
2. **Scale** (`analyze.ts`): a first pass at 1024 px finds and measures the cards; the photo is
   then re-run at the size the detector was trained for (~100 px per card).
3. **Deck symbols** (`icons.ts`): each badge's symbol is cut from the full-resolution photo and
   matched against the six deck symbols. This decides a card's deck; colour only breaks near-ties.
4. **Scoring** (`postprocess.ts`): classical geometry. Whole-board perspective from the badges,
   per-card fit of value/side/rotation against the printed dot layouts (each deck holds each
   design once), then the counting rule: a dot counts when it sits on a printed dot position of a
   found card and isn't partly covered.

`postprocess.ts` and `icons.ts` are ports of `tooling/detector/postprocess.py` and `icons.py`,
and the two must stay in step. The tests check that they agree.

## Tests

```sh
npm test                              # engine vs PyTorch, scoring vs the Python pipeline
node tests/browser/smoke.mjs          # app starts, runs, switches engines (no photos needed)
node tests/browser/offline-check.mjs  # service worker: install, go offline, reload, score a photo
npm run test:browser                  # the real app on the photos in training-data/games/
node tests/browser/engine-check.mjs   # GPU + CPU engines vs PyTorch in the browser
```

`npm test` uses the full data in `out/test-cases/` when present, otherwise the small committed set
in `tests/fixtures/`. `TACTA_TEST_DATA=fixtures npm test` forces the committed set. Both are
written by `tooling.export`; after changing the scoring, run
`tooling/.venv/Scripts/python -m tooling.export shipped`.

The browser tests build the app first and run against `dist/`. The exception is the engine
check, which runs on Vite's dev server because its test page imports the TypeScript sources.
They use headless Edge or Chrome with a throwaway profile, and block every hostname
except localhost. Screenshots and overlays go to `out/browser/`.

## CI and deployment

- `.github/workflows/ci.yml` runs on every pull request and push to `main`: type check, build,
  `npm test` (on the fixtures), the smoke test and the offline check.
- `.github/workflows/pages.yml` builds `dist/` and publishes it to GitHub Pages on every push to
  `main` (or by hand from the Actions tab). One-time setup: in the repository's Settings → Pages,
  set the source to "GitHub Actions".

The build uses relative paths (`base: "./"`), so the app works from the Pages sub-folder.
`sw.js` caches the whole app for offline use. The build gives it a new version hash whenever any
file changes, so phones pick up a new deploy on their second visit.
